# D0-A3 — ELSEWHERE 三岔路验收

开发及对照基准：`78030045ed86d4f2e3c2363d890ae6fd7ccc01ac`。范围见[冻结契约](../contracts/D0-A3-three-way-branch.md)。本阶段测试另用该基准的干净副本叠加 D0-A3 文件，未混入本地调试总览页改动。

## 空间与时间

- Main 沿用原主路中心线。共同隧道在 316 拍后逐渐扩宽；320 拍按插值坐标锁定路线，侧路从中心线平滑向左右各偏移 10.5 个世界单位。321.75 拍有三个实体八边形洞口，324 拍才开始过门。两道实体分隔只填洞口之间的间隙。Challenge 支撑框较密，Score 用间距更大的灯框；三个洞口各有文字标识。
- 流式 Tunnel 只移除与局部岔路重叠的原壳体，避免原侧壁挡住入口。348 拍起三条线连续收拢，352 拍在同位置、同朝向回到原路径。未选路的通道仍存在；选路前各预览第一道门，锁定后只绘制和判定所选门谱。
- 315 拍以插值后的实际距离与速度建立空间锚点：`s(beat) = s315 + (beat - 315) × unitsPerBeat315`。全通过的常速与持续 Boost 分别为 15.9375 与 23.109375 单位／拍。同一映射给摄像机、支路壳体和门采样；在此段内临时切换 Boost 仍影响原速度积分、距离计分和镜头效果，已放好的几何和分路内空间推进速率保持锚定。352 拍恢复按实际路程推进，并在 4 拍内平滑接回速率差。没有变更歌曲、音频时钟或固定步长。
- 分岔 Run Seed 流和道具流独立。固定 Seed 0 为左 Score、右 Challenge，Seed 1 为左 Challenge、右 Score。正常重试独立抽样，同一局暂停、恢复和重建 WebGL 不重抽。

## 门谱与得分

两段共同谱面保留原 Beat、Sector、Kind 和顺序。先应用旧 Easy 规则，再替换 `[320,352)` 的 11 道门。分路只对基础过门分和 CLEAN 乘倍率；Resonance 基于该结果额外加成一次。以下为不拾道具、不 Boost、全 CLEAN 的固定基准：

| 难度 | Main 门数／分 | Challenge 门数／分 | Score 门数／分 |
| --- | ---: | ---: | ---: |
| Easy | 140／66201 | 144／74201 | 156／70001 |
| Normal | 141／105326 | 145／118126 | 157／111406 |
| Hard | 141／156826 | 145／176026 | 157／165946 |

仅比较分路主体，普通倍率、满 Combo 和全 CLEAN 的收益为 4000／12000／7800 分，满足 Challenge > Score > Main。18 种组合均用键盘轴、150 ms 反应预算及实际碰撞通关：零失误、全门判定、S 级。Score 可以居中连续通过 24 道门。额外验证 Shield 抵挡 Challenge 漏门，Resonance 与 Challenge 的 2× 叠加顺序，以及 Score 路上的 Lumen 固定 +5000。旧四卷谱面摘要保留；仅 ELSEWHERE 的有效通关门数和分数基准随设计更新。

## 验证与资源

Windows、Node 24.22.1、Chrome 157；兼容性回归另含 Firefox 151、WinCairo WebKit 26.5 与两个移动模拟配置。

- 87 项 Vitest、41 项主浏览器回归、6 项发布检查。路径测试覆盖常速、持续 Boost 和中途切换，分流与汇合采样位置连续、每固定步移动小于 1.2 世界单位且切向变化小于 0.09 rad。20／60／120／144 Hz 驱动选路与结果相同。
- Chrome 图形测试用场景射线验证三块入口标识无遮挡：常速两种布局在 317.5 拍已全部可见，持续 Boost 样本在 319.5 拍可见；文字选路提示从 315 拍出现。锁定后可见门中心与所选路径误差小于 `1e-6`，固定拍截图可逐像素复现。上下文丢失、恢复和 BFCache 保留已选路线，退出、切卷和重开释放或重置状态。
- 960×540、DPR 1、low 的稀疏抽帧测试中，分路为 5 个临时 Mesh，共享原隧道外壳材质。第 325 拍采到 20–34 draw calls、约 13.6k–19.6k triangles；3 张标识纹理从 7 增到 10，退出后回到 7。9 次循环释放 45 个 Geometry、27 个 Texture 和 36 个 Material；同一速度与入口的重复样本计数稳定。首次未预热的稀疏绘制曾测到约 124–156 ms；在卷初始化预热两种材质程序、按正常顺序预绘制前帧后，两批采样约 13–35 ms。这是浏览器侧单次绘制调用耗时，不能当作 GPU 帧时间或手机性能。
- 与基准的生产构建逐像素比较：ELSEWHERE 分叉前（36 秒）及 DRIFT、DESCENT、ORBIT（各 83 秒）的高画质 Canvas 画面完全相同。生产 Runtime chunk 由 620.05 kB 增至 629.99 kB（gzip 160.31 → 163.75 kB）。
- 10 项兼容性用例、2 项资源／Shader 回归通过；116 个 Shader Handle 均释放。音频回归含 9 项 Transport 单测及 7 项 Chrome 用例。ELSEWHERE 在真实音频时钟下完整运行 210 秒，Main 141／141，全部 1792 个调度步完成，游戏与音频未因分路重启。WinCairo 的有声音频仍为 `BLOCKED`。

## D0-A4 试玩

优先比较常速和持续 Boost 时，能否在 HUD 提示后及时辨识左右入口；Boost 样本的三个实体洞口显露更晚。再试玩挑战路的连续转向、分路内临时 Boost 的体感、Score 的奖励是否符合定位，以及两条侧路汇合时的镜头舒适度。手机真机手感和实际听感尚未验收。

## 试玩调整

- 三个底部全息箭头和路线名从 315 拍持续到 323 拍。立体箭头与 Chakra Petch 文字平铺在镜头下方，保留实体边框，内部只有几道沿指向流动的半透明线。独立透视保留俯视角度和位置。分叉大厅输入横向上限每侧由 3.41 增至 9.41 个单位，选路阈值为 ±2.4。进独立洞口时逐步回到原截面。加宽仅发生在 314.65 拍的共同门之后，进入首门前已恢复普通碰撞坐标。
- 三路门谱各延后两拍，首门在 326 拍，比洞口晚约 1.99 秒；保留各路线门数、门距和奖励倍率。汇合自 349.5 拍开始，仍在 352 拍接回。挑战路装饰框变细、变暗，并增大间距，让玻璃开口更醒目。
- 旧种子映射能生成三种道具，正常开局也确实生成新种子。为消除连续重复的体验，同一游戏实例改为每组三次出场随机各发一种。未到出场点的重试不消耗抽取；固定时间和显式种子仍可复现。模型角度按绝对拍数设置，修正旧版随帧累加的转动。不增加道具名称提示。
- 三种输入方式的宽大厅测试、18 种分路全通关、桌面及 360 px 窄屏的全息标记测试通过。测量固定相机坐标和画布输出，验证后处理开关两条渲染路径，以及六份标记几何随卷释放。浏览器注入重复的 Lumen 种子跑 12 次出场，每组三次仍各见一种。原计分与成绩基准保持不变。
