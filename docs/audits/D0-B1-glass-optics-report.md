# D0-B1 R1 — ELSEWHERE 玻璃验收

对照基准 `88a2dfdf3229fc51007c4c4dd70f651769a6293f`，实施前与 `origin/dev` 一致。R1 只替换 ELSEWHERE 三种门的绘制。`collision.ts`、关卡、节拍、音频、道具和分路规则沿用基准。DRIFT、DESCENT、ORBIT 在相同时间和画质下的截图与基准逐像素一致。

## 几何与光学

- 每扇门使用一个索引网格，局部 `z = 0…0.38`。两个端面以八边形和开口轮廓三角化，四层轮廓在 `z = 0、0.055、0.325、0.38` 连接成两段倒角和一段垂直侧壁。端面向实体内退 `0.035`，中间 `0.27` 保持原通行截面。Square 和 Diamond 包含完整内壁。Iris 两条径向切边与内缩八边形、Hub 圆相交，暴露圆弧用 32 段侧壁连接。原始 Hub 圆弧弦高误差小于 `0.00008` 单位，严格碰撞边界仍由原 CPU 规则决定。径向侧壁使用网格轮廓裁切，避免在半开扇区的共面边被片元浮点舍入误删。
- Square 使用标准二维盒 SDF，Diamond 将局部坐标转到 45° 的正交基后使用盒 SDF。Iris 取到暴露 Hub 圆弧及两条有限径向边的最短距离。Hub 接缝和辐射缝共用 `r ≥ 1.02` 遮罩，遮罩作用于核心和 Halo；暴露圆弧作为开口边单独发光。八边形外框使用到有限轮廓线段的距离。端面开口继续使用 CPU 的严格不等式及 Iris 扇区编号。
- 线条覆盖取 `σ′ = sqrt(σ² + pixel²/12)`，`coverage = (σ/σ′) × exp(−d²/(2σ′²))`。`pixel` 由局部坐标的 `fwidth` 估计，窄核心在远处减弱并平滑变宽。L2 在靠近 L1 时衰减。沿用现有 Bloom、色调、Hit 混合、按拍和距离 Fade。

| 光层 | 轮廓 | σ 核心 / Halo | 发光权重 核心 / Halo | Alpha 增量 核心 / Halo |
|---|---|---:|---:|---:|
| L1 | 开口边 | 0.012 / 0.055 | 1.65 / 0.48 | 0.34 / 0.12 |
| L2 | 普通拼接与支撑线 | 0.009 / 0.033 | 0.58 / 0.16 | 0.14 / 0.04 |
| L3 | 外轮廓 | 0.007 / 0.022 | 0.31 / 0.09 | 0.08 / 0.025 |

全息线周期 `0.055` 单位，占空比 `18%`，约 `18.2` 条/单位、每片完整高度约 `107` 条。相位漂移 `0.65` 周期/秒。Shader 对周期脉冲在像素足迹内积分，足迹从 `0.50` 到 `0.95` 周期时平滑压低对比，随后收敛到平均覆盖。GPU 取样的近处、亚像素处时间对比（同一点 12 个相位，8 位 RGB 之和的极差）分别为 `74` 和 `0`。Hub 内同高对照的亮度差为 `0 / 0 / 0`。Square 样点的 L1、L2、L3 亮度分别为 `754 / 396 / 326`，Halo 与面材为 `182 / 80`。这些是指定色相下的局部像素读数。

## 碰撞、资源与截图

- 正视像素读回覆盖 Iris 八向、Hub 圆弧和两条径向边，以及 Square 四边、Diamond 四顶点和四条斜边两侧。Hub 的额外样点距边界 `±0.0005`。GPU 与 CPU 的采样判定无差异。Iris 的 24 个侧视读回在截掉远侧门面的条件下均检测到侧壁。射线单独验证 Square、Diamond、Iris 暴露圆弧和径向边在中间截面的距离，并确认倒角端部向实体退让。
- `VolumeScene` 持有懒加载网格缓存。Square 和 Diamond 各一份，Iris 每个方向一份，单卷最多十份。每道可见门持有一个 Mesh 和独立 ShaderMaterial；单次双面提交由同一个 Shader Program 服务。门退场仅释放自身材质。切卷、上下文重建和销毁时释放几何缓存。24 个交替中央门只引用两个 Geometry，门销毁期间共享几何释放次数为零。四次混合门切卷复查均为 Geometry / Texture / Program `23 / 9 / 10`；反复预热的 Shader 创建和删除请求均为 `134`。
- 对照图包含 Iris 远处（36 秒）与近处（79.1 拍）、Square（107.2 拍）、Diamond（168.2 拍）、Score（333.5 拍）。同一画质、固定种子和自动对准下，R1 的开口边比拼缝亮，旧粗横纹和 Hub 辐射光晕消失。Score 画面可辨认连续的方窗、菱窗。截图由测试输出到 `test-results/stability/`，仓库只保留复跑方法。

## 同机性能对照

Windows 10 x64 build 19045，Ryzen 7 5800H，Chrome 157.0.8103.38 headless，Playwright 1.61.1，AMD Radeon 核显通过 ANGLE D3D11 硬件 WebGL2（驱动 31.0.21921.1000）。960×540、DPR 1、固定仿真位置及可见门。每场景按旧→新→新→旧执行；每窗口预热 24 帧，采 480 帧 CPU，异步 GPU 计时每窗口 20 个整帧和 20 个场景样本。表中时间为各版本两窗口的分位数中位值，单位 ms。Draw Calls 和资源为整帧场景统计。

Score 样点有 12 道可见门，Mesh `24 → 12`，活跃门 Geometry `1 → 2`。新增三角形用于真实玻璃表面。整帧 GPU 中位接近基准，高画质 Score GPU P95 的单窗口范围为 `1.87–2.18 → 1.87–2.46 ms`，仍需更长窗口确认尾部差异。各窗口 RAF P95 约 `4.2–4.3 ms`，均无超过 `50 ms` 的帧。CPU 为固定画面更新与提交耗时。统计的 Geometry、Texture 和 Program 是对象计数，240 Hz 的采样节奏只反映该环境。运行时包为 `668.36 → 671.57 kB`，gzip `175.84 → 177.38 kB`。

复跑前构建基准及候选的 `build/client`、`build/harness`。基准 harness 的 `tests/harness/stability.ts` 使用本提交的同一套观测代码，其余基准代码保持原样。设置 `STABILITY_REFERENCE_DIR` 指向基准的 `build`，然后运行：

```sh
npm run build
npm run build:harness
npx playwright test --config playwright.stability.config.ts --grep '@glass|shader handle|bounded'
```

## 回归与人工观察

- `npm test` 通过 90 个单元用例和 44 个浏览器用例，包含四卷三难度的正常碰撞通关与固定结果、三岔路、拾取道具、资源回收和 GPU 像素对照。`npm run test:release` 通过 TypeScript Strict、SSG 构建及 6 个静态发布用例。上述性能与资源套件通过 4 个用例。
- 50 个相关兼容用例完成。Chrome 157、Firefox 151、WebKit 26.5 及两种移动模拟的实际门体像素对照均为 `PASS`。可控浮点帧缓冲、MSAA、Shader 故障和上下文丢失的回退或恢复符合现有预期。
- 音频生命周期和离线信号套件完成 16 个用例，四卷的信号和调度回归沿用既有基准。本轮未重跑四首实时全曲。WinCairo 无 AudioContext，有声用例为 `BLOCKED`，无声路径通过。Firefox 的 OfflineAudioContext 暂停/恢复 API 不可用，对应离线断尾检测为 `BLOCKED`。

人工验收仍需在真实高刷新率和移动屏幕上观察 Boost 时的远近细线、极斜视角的厚度，以及 Score 叠门和不同色相下的开口可读性。R2 再处理玻璃运行时纹理。
