# D0-B2-F1 — Camera & Gate Spatial Stability

基准为 `dev@9a9a29eb1601438ef4fcdf85749eb63589d6618e`。在 Windows 10、Chrome 157、Playwright 1.61.1 中，用同一套浏览器探针在基准和修复版采样。基准未通过新增的 FOV 跳变断言。运行 `npm run build` 和 `npm run build:harness` 后，用 `npx playwright test --config playwright.b0.config.ts tests/browser/camera-gates.spec.ts` 复跑。日志中的 `CAMERA_GATES` 给出时间序列、世界坐标变化和碰撞截面数据。

## 镜头

旧镜头把 `(1 - beat % 1) ** 4` 用作 3.4° 的 FOV 脉冲。它在整数拍从接近 0 跳回 1。Shift 还会直接切换 7°。三岔路宽度项随路口曲线连续变化，Roll 由固定步阻尼推进，路径采样在相邻截面之间插值。受击位移仅在受击后的短窗口出现。关闭受击随机偏移后仍能复现整数拍抖动。

观光取消镜头节拍项。Standard 改为连续的 `0.65 × ((1 + cos(2π × beat)) / 2)²`，幅度为 0–0.65°。Boost 的 7° 采用时间常数 180 ms 的指数响应，由仿真时间推进。碰撞或完曲转场保留最后一个游戏 FOV，回到菜单恢复基础 FOV。隧道与玻璃的节拍光效继续使用原有驱动。

## 门的位置

旧投影把整段剩余时间按当前速度外推。玩家正常接近时，相对距离 `ahead` 应缩短，门中心在路径上的位置 `along` 可独立测量。基准中按下 Shift 后，速度变化乘以数秒的提前量，使可见门先向前滑，有时比玩家前进得还快。松开时则反向滑。分叉内的路线门已经由道路锚点固定。

新投影以巡航参考速度推算剩余行程，仅对当前 Boost 速度增量积分，预览中的增量按 320 ms 时间常数衰减。剩余时间趋于 0 时，预测截面收敛到玩家所在截面。分路门继续使用 `BranchPath` 固定截面，共同后段的投影和玩家位置共享四拍汇合修正。门在判定后保存实际穿越截面，淡出期间保持该世界位置。Boost 倍率、速度阻尼、观光比例、AudioTransport、门的判定拍点、计分和玻璃材质沿用现有规则。

四卷共 18 组测试，涵盖常规路径和 ELSEWHERE 分叉前、入口、支路、汇合、汇合后。每组先无外部输入，再按住 Shift 0.5 s 后松开，跟踪同一个可见网格。自动对准用于保证完整观察，碰撞仍然开启。下表记录最大单帧位移，单位为世界单位。

| 量测 | Standard 基准 → 修复 | Sightseeing 基准 → 修复 |
|---|---:|---:|
| 无 Boost，门世界位移 | 0.0144 → 0.0144 | 0.0143 → 0.0143 |
| 按下，门世界位移 | 3.6658 → 0.3433 | 1.9013 → 0.1145 |
| 松开，门世界位移 | 1.1470 → 0.1026 | 0.6096 → 0.0379 |
| 门与相机沿轨距离增大 | 3.2275 → 0 | 1.7547 → 0 |
| 过门后淡出期间，门相对穿越点的最大漂移 | 0.1008 → 0 | 0.0385 → 0 |

支路门的世界位移仍为 0。共同门中心与道路采样位置、判定拍与门的穿越截面在样本中的误差均小于 `1e-6`。DRIFT Standard 从第 56 拍持续 Boost 到第 64 拍，比巡航多前进 55.024 单位。Sightseeing 从第 56 拍到第 70 拍相差 32.975 单位。两组都在各自原判定拍穿越玻璃，真实落点不同。因此普通门仍会随可变速度逐步调整。若要把它们全部固定在世界坐标，可以把纵向推进锁到拍点，但持续 Boost 的净位移会改变；也可以在到达固定门时判定，但玩家的判定节拍会改变。两种做法均涉及玩法取舍。

## 回归

`npm run typecheck`、`npm test`、`npm run test:release` 均通过，共 115 项单元测试、52 项浏览器测试、6 项静态站点验收。包含四卷 Standard 三难度、四卷 Sightseeing 与 ELSEWHERE 三路的完整碰撞通关，以及真实 WebGL 的开口与 CPU 碰撞比对。

另通过 40 项跨浏览器图形兼容性用例、3 项密集玻璃门与 GPU 资源用例。音频启动、暂停恢复和长帧回归执行 6 项。Windows WebKit 的原生 AudioContext 缺失，相关有声路径为 `BLOCKED`，已验证无声启动与恢复。20–144 Hz 是同一浏览器中受控的提交频率，移动真机与高刷新率屏幕上的观感仍待实测。

Chrome 的真实 AudioContext 下，DRIFT Standard 和 Sightseeing 均调度 896 个十六分音符步，在原定 140 秒、第 224 拍结算。Standard 40 门全过，得分 23,928。Sightseeing 13 门全过，保留 5 条命。
