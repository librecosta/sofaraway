# D0-B2 — Sightseeing Mode 验收

实施前核对本地及远程 `dev`，均为 `f0806d12a58f22e149dacc9161712d0a5ba8fe4a`。测试使用 Windows 10、Node 24、Playwright 1.61.1。真实音频测试使用本机 Chrome 和实际 AudioContext。

## 时间、速度与门谱

Runtime 用同一个 AudioTransport 驱动 60 Hz 仿真。拍点、章节、场景色相、原曲结束和结算依然走原时间。观光启动速度为 `8` 单位/秒。仿真从完整 Normal 门谱按已过拍点推进参考计数，选路后只纳入所选路线的完整门谱。计数用于原有 `24 + min(通过进度 × 0.22, 10)` 曲线。目标速度应用原 Boost `1.45` 倍率和观光 `1/3` 倍率，再按原阻尼更新。实际稀疏门数和失误不会额外减慢参考曲线。对照无失误 Standard 的速度和沿轨距离，四卷及各分路在相同 Boost 输入下均为三分之一。20、60、120、144 Hz 提交相同时间产生相同状态，键盘、指针和触摸横向输入保持原响应。

每个有门章节的完整 Normal 门谱按等宽区间取中心门，保留原拍、方向、轴和门型。Main 取 Square、Diamond、Iris 各一道，Challenge 保留方向变化和中央门，Score 每隔三拍保留一道并交替使用两种中央开口。当前最短相邻间隔为 3 拍。用 150 ms 反应延迟和常规方向输入，四卷和两种布局下的各路线都能完整通过。每卷起始 5 条命，连续漏门实测扣完 5 条并正常终止。

## 分叉、道具与成绩

观光模式复用原分叉路径、壳体和资源管理，在第 315 拍固定沿轨比例，第 320 拍用原插值输入选路，第 352 拍汇合。两侧分别偏移 `10.5` 单位，三个独立八边形通道外壁的横向间隙为 `3` 单位。观光模式将入口全开移到第 `325.25` 拍，开始汇合移到第 `347.25` 拍，给短纵向轨道留出渐变区。观光与 Standard 都沿用锚点锁定语义。分叉期间按进入时速度布置拍点，途中的 Boost 切换由汇合后的速度接缝吸收。测试覆盖常速、持续 Boost 和途中切换，确认中心线连续、路线门位置与路径吻合，原选路拍点及汇合拍点可达。两种布局在选择前均能看见三个入口，分叉离开后可回收网格。暂停、恢复、WebGL 上下文重建及往返缓存保留已选路线和门数。

Shield、Resonance 和 Lumen 都在第 `306.66` 拍经主动输入拾取，测试覆盖每种道具与两种 Challenge 朝向的组合。最近门仍在第 `309.32` 拍，巡航时与道具相隔约 `14.1` 单位。Shield 抵消一次扣命，Resonance 在通过下一道门后消耗一层，Lumen 加 `5000` 分。投影沿用与门相同的沿轨映射。

选择器支持鼠标、键盘和窄屏布局，独立保存模式。切回 Standard 恢复此前难度。观光结算显示 SIGHTSEEING，并保留分数、门数、连击和准确率。实际 Runtime 结算测试以 `17` 分为现有 Best，观光超分时保留 `17`，Standard 超分时更新 Best。

## 回归结果

- `npm run typecheck`、`npm test` 和 `npm run test:release` 通过，包含 115 项单元测试、51 项浏览器测试和 6 项生产静态站点验收。
- C0-A 的初始化、运行、GPU 能力降级、门型 Shader、上下文恢复和移动视口回归共通过 52 项。Windows WebKit 的有声播放为 `BLOCKED`，已验证显式无声路径。
- C0-B 和 D0-B1 的 3 项资源与画面测试通过。与基准使用相同浏览器及采样条件，四卷 Standard 定点画面逐像素一致。重复生成门的 geometry、texture、program 计数稳定在 `23 / 9 / 10`，Shader 预热测试的 134 个句柄均完成释放。
- C0-C 的启动、调度延迟和离线音频回归执行 16 项。Windows WebKit 的实时 AudioContext 路径、Firefox 的离线暂停和恢复因接口缺失标记为 `BLOCKED`。DRIFT 观光模式的 Chrome 全曲实播单独通过。
