# T0 Bilibili Toy compatibility audit

2026-11-28 · SoFarAway `dev` at `5aafe3c`, with the existing local mobile orientation changes present in the probe.

## Decision

An independent player-only Toy build is feasible. A disposable Vite build loaded the shared game under a nested static path with no SPA fallback. The production ORBIT renderer drew the fixed AURORA scene with WebGL2, RGBA16F and 4× scene MSAA in Chrome and Playwright WebKit. Chrome started a short STARWAKE flight with sound and recovered from simulated suspension and an actual context-loss test. Playwright WebKit lacked Web Audio in this environment and could start the same flight using the game's silent fallback.

The current viewport cannot be packaged directly for players. It still reads Web launch parameters, reaches the recorder and offers off-site links. A local probe built with `VITE_REGION=cn` also included the public-security registration link in its JS. The Toy implementation needs an independent entry, a compile-time player-only boundary, a region-and-target compliance gate and the shared locale layer. The authorized SDK reference and physical Bilibili container checks remain open. Review the [distribution proposal](../contracts/T0-distribution-localization-proposal.md) and [player features proposal](../contracts/T0-toy-player-features-proposal.md).

The FAQ lists a 50 MB package limit with larger allocations by approval. The entry HTML itself has an unpacked 1 MB cap. Use relative URLs and case-exact filenames. Current platform routing supports hash navigation. History URLs need real packaged files. Build content-hashed assets, keep a small entry and validate media types and allowlisted extensions on hosted preview. Separate the cover and icon from the game ZIP. The linked orientation demo also presented a login gate. This audit used the public platform descriptions and inspected Bilibili's public UMD client `toy-sdk.js` (147,899 bytes, SHA-256 `e88a5ca58ff4eab74990f75e165467d4b2efc9ebd224e0f41fe06e6799848e4d`). The file exposes `window.toy`. Load only the platform-approved SDK from the Toy adapter, with a bounded failure path and no impact on entering the game. ## Local probe and preflight

Environment: Windows 10 build 19045, Node 24.22.1, Vite 8.3.8, Chrome 158.0.8127.37 on ANGLE AMD Radeon/D3D11, and Playwright WebKit 26.5. Pixel 7 and iPhone 15 profiles were desktop emulations. The ignored prototype used a Vite root with `base: './'` and `publicDir: false`. Its entry mounted the existing `GameViewport` in a `MemoryRouter` using the current URL path/search/hash. It imported no Web SSG route tree and intentionally retained Web diagnostic hooks for inspection. This probe measures compatibility, and it is distinct from the proposed clean Toy artifact.

| Check | Result |
| --- | --- |
| Nested static assets | All three browser profiles loaded `/toy/t0-check/index.html`, hashed JS, a dynamically imported game runtime, CSS and WOFF2 fonts with matching MIME types. Missing assets and nested routes returned HTTP 404. Requested game resources stayed under the mount. |
| ORBIT rendering | High fixed capture `vol=orbit&q=high&t=120&dbg=1` drew at beat 256. The renderer reported RGBA16F, 4× MSAA scene targets, 11 programs and no GL error in each profile. Draw calls were 133 desktop, 79 Pixel emulation and 81 WebKit emulation in their respective viewports. The contexts reported max 3D texture size 2,048 and exposed instanced draws. Counts here characterize the smoke fixture. |
| Trusted Start | Desktop Chrome and Pixel emulation advanced from beat 0 past 1 with no silent fallback reported by the transport. WebKit emulation exposed neither standard nor prefixed AudioContext here. The audio error dialog offered silent play and the run advanced after selecting it. |
| Resume, resize and context | In both Chrome profiles, simulated persisted `pagehide/pageshow` paused and resumed at the same run offset. `WEBGL_lose_context` loss and restore returned both to advancing flight. Pixel emulation resized the Low canvas from 412×839 to 839×412 after swapping the viewport. These tests did not reproduce physical rotation or an OS suspension. |
| Storage and platform APIs | All profiles passed a localStorage round trip and opening IndexedDB and exposed `navigator.locks`. An isolated sibling test page at the same local origin could read the same localStorage key. This establishes path behavior locally. Real Toy storage origin and partitioning are open. Chrome exposed browser fullscreen/pointer-lock APIs. WebKit emulation exposed neither and had no `screen.orientation.lock`. Native permissions were not tested. |
| Local packaging | ZIP root `index.html` plus hashed resources, BSD-3-Clause and third-party/OFL notices. Entry about 0.4 KB, ZIP 463,683 bytes. Official doctor returned `ok: true` with zero findings. A companion `VITE_REGION=cn` packaging test found the compliance link only in the CN prototype JS, confirming the need for an independent target gate. |

The release decision needs a Toy-enabled account, the authorized reference and permission to upload a link-only preview, followed by physical Android/iOS App and desktop Bilibili Web testing. Enable ranked play, cloud save and result-image sharing only after the corresponding hosted tests and policy checks.
