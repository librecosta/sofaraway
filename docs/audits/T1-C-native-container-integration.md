# T1-C — Native container integration

Baseline `ee2208f`. The official publisher reference declares a self-initializing CDN script that exposes `window.toy`. Capability checks are asynchronous, state updates are complete snapshots, and both state and close subscriptions return unsubscribe functions. `setContainerMode` accepts a combined orientation and immersion request. Its Promise reports acknowledgement. The current state or a subscription update confirms the result. The FAQ lists App 9.9.0 or later for container controls. [Publisher SDK reference](https://www.bilibili.com/toy/publish/sdk) · [Bilibili FAQ](https://www.bilibili.com/opus/1241171666570051585) · [Official CLI and tools](https://github.com/bilibili/toy)

The publisher route gates the rendered reference behind Toy permission. The public publisher JavaScript included the official reference and TypeScript declaration. They agreed with the public CDN SDK on `isSupport`, `getContainerState`, `onContainerChange`, `setContainerMode` and `onPageClose`. The CDN client matched T0's SHA-256. The FAQ mentions capsule coordinates, while the current public SDK normalizer and declared container state expose viewport, edge insets, orientation, immersion, device type and changed fields. No capsule rectangle is exposed through those methods. The game moves top-right controls away from that corner and applies the reported edge insets directly in CSS pixels. [Public CDN SDK](https://s1.hdslb.com/bfs/seed/toy/app/sdk/toy-sdk.js)

## Implementation

- The [Native Adapter](../../toy/native.client.ts) loads or reuses the official script only on Bilibili HTTPS Toy pages in the App channel. Loading and probing are time-bounded and independent of game startup. Capability gates keep the browser path available. Snapshot comparison and read sequencing guard against duplicate or late responses. The page-close notification is best-effort. Browser visibility and page lifecycle are still observed.
- Player gestures drive native mode requests, including an atomic landscape and immersive request. The default orientation preference remains landscape. A matching state enables the next Start gesture. Ordinary viewport changes update Canvas, Camera, PostFX and input mapping. A real orientation change clears input and safely pauses a run with its current score, lives, Auto Boost and audio offset. Unmount and close release the active canvas, audio and subscriptions. [Player adapter](../../toy/ToyPlayer.tsx) · [Runtime](../../app/game/runtime/GameRuntime.client.ts)
- Mock and Native implement the same platform contract. The offline [Dev Console](../toy-development.md) can resize the player, display a capsule and interaction bar, drive requests from both sides, simulate failure or timeouts, and suspend, resume or close the session. The Toy ZIP excludes this console and all Debug features. Web bundles exclude the SDK and Toy adapter.

## Bilibili App checklist

- Open a link-only preview in recent Android and iOS Bilibili apps. Check the actual iframe URL, official CDN script availability, and capability results. Repeat on desktop Bilibili Web and an older App client for the browser fallback.
- Launch in portrait and check that the game stays in portrait until a player uses **Play Landscape**. Verify one landscape plus immersive transition, explicit Start with sound, portrait selection in Settings, and exit from immersion.
- Check menu credits and audio, lower controls, HUD/Pause, Settings, Credits, errors and Results against the real capsule, follow controls, notches, home indicator and bottom interaction bar. Exercise portrait, landscape, immersive and standard host presentation. Verify tablet and foldable viewport changes when available.
- Rotate and background the App during a short scored flight. Confirm input clears, rotation pauses, lives and progress stay intact, and audio resumes at the same position. Close and reopen and check local settings/records, fresh resources and stable WebGL.
