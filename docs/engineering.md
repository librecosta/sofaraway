# Engineering architecture

Use the [player README](../README.md) for controls and diagnostics, and the [verification guide](verification.md) for executable checks. [`package.json`](../package.json) and its lockfile define the supported toolchain and exact dependency versions.

## Runtime boundaries

- **Application** owns route state, accessible menus, HUD and persistence. `GameViewport` loads the runtime after hydration and consumes read-only snapshots through `useSyncExternalStore`. React issues commands through [`GameRuntime`](../app/game/contracts.ts) and stays outside the fixed-step and drawing loops.
- **Runtime** owns the canvas session, renderer, RAF, input listeners, run lifecycle and audio transport. Retries and volume switches reuse the runtime. Async work must respect the current generation. Context restoration rebuilds GPU resources while retaining the run, including the random layout. BFCache suspends the runtime, and permanent teardown disposes it.
- **Simulation** owns deterministic charts, movement, crossings, lives, scoring and results. It runs without a browser. [`Path`](../app/game/graphics/path.ts) and [`BranchPath`](../app/game/graphics/branch-path.ts) are shared Three.js vector math that can be imported by Node. WebGL, DOM input and audio stay in their client modules.
- **Graphics** owns the visual scene and reads simulation state. Volume-owned materials, textures and reusable templates outlive streamed chunks. Chunks dispose their own geometry. Debug previews use the runtime generators with their own resource owners. ELSEWHERE-specific art belongs in its own paths and presets.
- **Audio** owns Web Audio activation, the per-run output bus, scheduling and synthesis. Runtime aligns its anchor to the same run timeline as simulation. Audio callbacks have no authority over scoring or crossings.

## Time, space and recovery

[`clock.ts`](../app/game/core/clock.ts) defines a monotonic run timeline and 60 Hz simulation. User pauses, background suspension and graphics interruptions freeze the timeline. Ordinary stalls leave bounded catch-up debt. Audio skips expired scheduling steps and resumes on its original grid. A later audio interruption can fall back to silent play and offer a gesture to restore sound at the current offset.

[`reference-track.ts`](../app/game/core/reference-track.ts) converts authored beats into fixed main-path stations. Simulation advances by arc length, interpolates the player's local position at each crossing and judges each event once. Boost changes arrival time. Musical time still drives sections, light and the song end. On branches, the same station maps to route-specific arc length, including the length difference carried through the merge. The [world-space contract](contracts/D0-B2-F2-world-space-gameplay-graceful-recovery.md) records the model and why it replaced beat-locked crossings.

DAYBREAK, DESCENT and ORBIT use a 1.15× longitudinal reference in Impossible Standard. Cruise meets the authored cues while Boost retains the same proportional lead as the base difficulties. The gates, centerline, junctions and world bounds use that reference. Side routes still take their measured travel time. ELSEWHERE uses its original station layout and the separate Impossible Encore.

Standard has three base difficulties and Impossible, with a faster speed ramp and added gates between Hard anchors. See [DAYBREAK Impossible validation](audits/D1-B2-validation.md) for its chart and ending contract and the [DESCENT facility contract](contracts/D2-A0-descent-facility.md) for its CONTROL accents. Sightseeing uses five lives, one-third forward speed, a sparser chart and the same song duration. The fixed pickup, branch layout and obstacle shapes have separate sources in [`pickups.ts`](../app/game/core/pickups.ts), [`branches.ts`](../app/game/core/branches.ts) and [`collision.ts`](../app/game/core/collision.ts). Branch and pickup randomness use independent streams. Rendering and collision must agree on the opening and spatial station of each gate. Technical recovery can neutralize an unobservable crossing without rewarding or penalizing the player. See [`simulation.ts`](../app/game/core/simulation.ts) for the results semantics.

Showcase runs Standard Impossible with scoring disabled. The [pilot](../app/game/core/showcase-pilot.ts) plans through the real openings on the selected seeded branch, supplies ordinary steering and Boost input on every fixed tick, and remains subject to collision even while catching up. The runtime uses the shared music transport and keeps the flight HUD and all record writes disabled. For reproducible browser captures, `?mode=showcase&route=bonus&seed=1` selects the route and seed.

| --- | --- |

| Preferences, diagnostics and records | [`settings.client.ts`](../app/game/runtime/settings.client.ts) parses settings. [`records.client.ts`](../app/game/runtime/records.client.ts) owns the versioned Best and Last records. Storage is optional. Sightseeing and technically neutralized runs are ineligible to update a Standard Best. |
| Visual assets | Generate game geometry, materials and sound at runtime. Fonts, their notices and documentation screenshots are checked-in assets. Keep writable test globals in [`tests/harness/`](../tests/harness/) and its separate output. |
| DAYBREAK | The [production contract](contracts/D1-A0-daybreak-production.md) describes the shared score and rhythm events. The [gameplay and world continuity contract](contracts/D1-B0-daybreak-gameplay-world-continuity.md) defines the spatial layout, ending and cabin streaming. The [D1-B1 validation](audits/D1-B1-validation.md) records the current gate choreography, junction lighting and record ID. |
| DESCENT | [CONTROL](../tools/music/descent/README.md) supplies 136 BPM, 384 beats and seven sections to the shared Volume, Chart and ReferenceTrack. Its production events drive structural lighting. The [facility and glass contract](contracts/D2-A0-descent-facility.md) defines the authored path, streamed rooms and static gate openings. |
| ORBIT | [STARWAKE](../tools/music/orbit/README.md) supplies the frozen 128 BPM, 384-beat score. The [aperture contract](contracts/O0-B1-starwake-apertures.md) defines its own event chart, real beveled holes, RINGBREAK routes and bounded Encore. [OrbitWorld](../app/game/graphics/orbit-world.client.ts) protects all three branch centerlines and gate sightlines. The [cosmic setpiece contract](contracts/O0-C1-cosmic-setpieces.md) defines seven fixed world compositions, shared macro LOD and astronomical depth. The [projection and beacon contract](contracts/O0-B2-astral-stability.md) defines its stable lens and Split entry beacons. `/debug/#orbit` previews the same world; `/debug/#gates-orbit` inspects production glass. Density-rebalanced runs use `orbit-starwake-density-v2`, preserving all previous ORBIT record versions. The original chart skeleton remains its motion reference, keeping world stations fixed. |
| Audio Inspector | [`app/game/debug/audio/`](../app/game/debug/audio/) owns debug-only transport, waveform extraction, monitoring and stem WAV export. All four production scores and voices are reused: ELSEWHERE has 7 stems, DAYBREAK 6, CONTROL 8, STARWAKE 7. Optional routing separates each instrument's dry and wet paths before the unchanged shared master processing; kick ducking remains active even when Kick is muted. Waveforms tap those actual pre-master stem buses and the final Master, including effect tails. Unity stem exports pass through the shared master individually, so nonlinear compression prevents summing them to reconstruct the master. Offline jobs are serialized with bounded pre-roll blocks and a bounded volume peak cache. ORBIT uses the approved M1-F1 as its sole production STARWAKE; no audition selector remains. |
| ELSEWHERE glass and scenery | The [glass optics](contracts/D0-B1-procedural-glass-optics.md), [micro-surface](contracts/D0-B1-R2-micro-surface-polish.md), [surface material](contracts/D0-B3-M0-material-surface-dressing.md) and [corridor atlas and S-curve](contracts/D0-B3-A1-F2-long-corridor-lighting-s-curve.md) contracts explain the current design. Simulation and rendering share one path for the selected mode. Theme geometry uses fixed reference stations and Color Score uses song time. |

ORBIT's [lighting contract](contracts/O0-D1-starwake-lighting.md) describes the [score](../app/game/core/orbit-lighting.ts), which reads frozen STARWAKE events through bounded envelope buckets. Slow section targets drive the existing key/fill rig; sustained LEAD/PAD/SWEEP and restrained drum accents modulate spatially masked rock surfaces and the six existing gas layers. World station still owns landmark presence and streaming. Music never changes geometry, FOV, optical depth or gate openings. Dynamic Lights off restores the neutral rig; Reduced Motion retains slow section illumination without traveling accents. The audio-output position feeds the same score in gameplay and `/debug/#orbit`, where world station and music beat can be controlled independently using the shared AudioTransport.
